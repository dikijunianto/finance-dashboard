# v1.3: actual-aware Plan

## Attribution and preserved money flow

`src/lib/plan-categories.ts` is the single source of six canonical categories.
New expenses require a category; old `expenses.category` is retained unchanged
on edits. Nullable `expenses.plan_category` controls attribution only.
Metadata-only edits (including unlinked/inactive-account historical expenses)
do not replay account movements. Economic edits retain existing reconciliation.

Bills and debt payments use `bills_debt` automatically. Investments/Savings
transfer attribution is stored against the logical transfer UUID in
`transfer_plan_attributions`, in the same money transaction. No attribution is
stored on individual ledger legs. Ordinary transfers have no attribution.
Liquid-to-investment transfers automatically use Investments; explicit Savings
requires a liquid source and non-investment destination. Account metadata edits
cannot retrospectively reclassify an attributed transfer.

## Shared query and formula

Plan and Overview use `getPlanUsage`. Actual dates determine the selected month;
funding_month only determines funding. Expense usage comes from current expense
rows, bill/debt usage from current paid source records. Transfers count the
original outgoing leg once, require a matching incoming leg, and are excluded
if any reversal exists, including in a later month.

For each category:

- Used = attributed expenses + applicable payments/transfers.
- Remaining = max(Planned - Used, 0).
- Overage = max(Used - Planned, 0).
- Bills/Debt usage includes paid bills and debt payments, even though Reports
  exclude principal debt payments from Spending.

Protected Bills/Debt = max(remaining Bills/Debt allocation,
unpaid current-billing-month active bills + outstanding current-month active
debt installments, capped by remaining debt). Monthly debt payments reduce only
their own debt installment.

Safe-to-Spend = active liquid balances - protected Bills/Debt - remaining Living
- remaining Savings - remaining Investments - remaining Buffer.

Lifestyle is not reserved. Negative Safe-to-Spend remains visible. Without any
Plan rows, Safe-to-Spend is null/Not available. Zero-valued saved Plan rows are
still an explicit Plan. Unknown legacy attribution does not consume a guessed
bucket and produces a review warning.

Reports definitions remain income by receipt date; Spending = manual expenses
+ paid bills; Outflow = Spending + debt payments; Net = Income - Outflow.
Internal transfers, opening balances, adjustments and reversal rows do not
become cash-flow income/spending/outflow.

## Migration and rollout

Apply `0005_last_darkhawk.sql` before releasing new code. It has NOT been applied
to production by this work. It adds one nullable expense column and a small
logical-transfer attribution table. Backfill matches exact case-insensitive
canonical names and approved aliases only: Living/Makan/Kebutuhan/food;
lifestyle/entertainment; investment(s); saving(s); buffer; bills_debt.
Ambiguous categories (Give, Style, Keinginan, Transport, custom names) stay null.
Legacy category text is preserved. Backfill never touches balances, funding,
payments, debt totals, allocations or movements.

Legacy investment attribution requires one intact owned pair, active liquid
source, investment destination, and no reversal. Old Savings transfers are
not guessed. Historical inactive/ambiguous transfer eligibility remains
unattributed rather than inferred. Existing old code remains schema-compatible.
Rollback: restore previous application code and leave additive metadata intact;
no financial rollback/replay is needed. Backfill statements are retry-safe;
DDL itself is applied once by migration tracking, as for existing migrations.
